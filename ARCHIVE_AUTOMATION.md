# Monthly Archive Automation

Last updated: 2026-06-04

LetterBrick monthly archives are generated by GitHub Actions with Firebase
Admin SDK.

## Schedule

Workflow:

`.github/workflows/monthly-archive.yml`

Default schedule:

- UTC: day 1, 16:10
- KST: day 2, 01:10
- Target archive month: previous month

The job runs after the month has fully closed, then writes CSV files to Firebase
Storage and metadata to Firestore.

## Required GitHub Secret

The workflow requires this repository secret:

`FIREBASE_SERVICE_ACCOUNT`

Value: the full Firebase service account JSON.

The service account must be allowed to:

- read Firestore `records/{uid}/entries`
- write Firestore `admin_archives/{month}`
- write Firestore `admin_archive_runs/{runId}`
- write Firebase Storage `admin_archives/{month}/{filename}`

Optional notification secret:

`ARCHIVE_SLACK_WEBHOOK_URL`

When this secret is present, the workflow sends a Slack notification after every
archive run. When it is absent, the workflow still writes a GitHub Actions
Summary and skips Slack.

## Manual Run

In GitHub Actions, run `Monthly Archive` manually.

Inputs:

- `month`: optional `YYYY-MM`; empty means previous month
- `dry_run`: when true, reads Firestore and builds metadata without writing
  Firestore or Storage

## Local Commands

Dry run:

```bash
FIREBASE_SERVICE_ACCOUNT='{"type":"service_account",...}' npm run archive:monthly:dry
```

Specific month:

```bash
ARCHIVE_MONTH=2026-05 FIREBASE_SERVICE_ACCOUNT='{"type":"service_account",...}' npm run archive:monthly
```

## Firestore Writes

Monthly archive document:

`admin_archives/{month}`

Key fields:

- `scheduleStatus`: `running`, `success`, `error`, `partial`, or `dry-run`
- `uploadStatus`: `uploaded`, `partial`, `error`, or `dry-run`
- `lastRunId`
- `lastRunAt`
- `lastCompletedAt`
- `lastFailedAt`
- `lastError`
- `retryCount`
- `recordsStorage`
- `sogamStorage`

Run log document:

`admin_archive_runs/{runId}`

Each run stores status, counts, Storage results, and failure diagnostics.

## Notifications

Workflow notification step:

`npm run archive:notify`

The archive generator writes `archive-result.json`, then the notification script
reads it and reports:

- status: `success`, `partial`, `error`, `fatal`, `dry-run`, or
  `missing-result`
- archive month
- record count
- sogam count
- upload status
- GitHub Actions run URL
- admin dashboard URL
- failure reason when present

Notification destinations:

- GitHub Actions Summary: always written
- Slack: sent only when `ARCHIVE_SLACK_WEBHOOK_URL` is configured

## Admin Audit View

The admin dashboard `Monthly Archive` section now includes:

- recent missing-month detection for the previous 6 archive months
- upload health for `error` and `partial` archive states
- recent failed scheduled run count
- duplicate scheduled run detection by month
- month-level detail view
- run history from `admin_archive_runs`
- metadata checks for required Storage paths and download URLs
- restore/download checklist for records and sogam CSV files

This view does not rewrite data. It is an operator-facing inspection layer for
archive verification and recovery planning.

## Restore Runner

Workflow:

`.github/workflows/archive-restore.yml`

The restore runner reads archived CSV files from Firebase Storage and rebuilds
missing Firestore entries under:

`records/{uid}/entries/{restoreDocId}`

Default mode is dry-run. Dry-run reads archive CSV files, validates rows, checks
duplicates, writes a restore run log, and does not write user entry documents.

Manual workflow inputs:

- `month`: required `YYYY-MM`
- `commit`: false for dry-run, true for Firestore write
- `confirm`: required only when `commit=true`; must equal `RESTORE_YYYY-MM`

Local dry-run:

```bash
RESTORE_MONTH=2026-05 FIREBASE_SERVICE_ACCOUNT='{"type":"service_account",...}' npm run archive:restore
```

Local commit:

```bash
RESTORE_MONTH=2026-05 RESTORE_COMMIT=true RESTORE_CONFIRM=RESTORE_2026-05 FIREBASE_SERVICE_ACCOUNT='{"type":"service_account",...}' npm run archive:restore:commit
```

Restore safety controls:

- commit requires both `--commit` and `RESTORE_CONFIRM=RESTORE_YYYY-MM`
- duplicate detection checks existing `records/{uid}/entries` by date and
  sentence before writing
- restored document IDs are deterministic hashes, prefixed with `restore_`
- restored documents include `restoredAt`, `restoredFromArchiveMonth`,
  `restoredRunId`, and `restoreSource`
- restore logs are written to `admin_archive_restore_runs/{runId}`

Restore input files:

- records CSV is required
- sogam CSV is optional and is merged by `uid/date/sentence`

The admin archive detail view shows recent restore runs for the selected month.

## Storage Writes

CSV files are uploaded to:

`admin_archives/{month}/letterbrick_archive_records_{month}.csv`

`admin_archives/{month}/letterbrick_archive_sogam_{month}.csv`

The script creates Firebase download-token URLs so the admin dashboard can show
direct CSV links after the scheduled job completes.
